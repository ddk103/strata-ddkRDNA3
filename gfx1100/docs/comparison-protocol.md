# 游戏特化 Q4  vs  UD-IQ4_XS-v31 —— 全面对比方案

> 目的：用**你自己的游戏任务**判断新量化值不值得替换现有模型。
> 原则：一次只换一个变量；能盲评就盲评；过不了线就不替换。

---

## 0. 前置：新量化还要一个 Strata pack

量化产出的 GGUF **不能直接给引擎用**，还要按现有结构打一个 pack：

```powershell
E:\Strata\tools\hf-venv\Scripts\python.exe E:\Strata\src\Strata-rdna3-main\tools\iq_pack.py ^
  --gguf H:\models\qwen38fn-game-q4-00001-of-0000X.gguf ^
  --out  D:\Strata-data-v31\packs\qwen38fn-game-q4
```

现有 pack 的内容（供对照）：

| 文件 | 大小 | 说明 |
|---|---|---|
| `dense.bin` | 1,417 MB | 打包后的稠密张量 |
| `conversions.json` | 0.2 MB | 转换记录 |
| `index.txt` / `native_experts.txt` | 极小 | 索引 |
| `tokenizer/` | 目录 | 分词器 |

pack 建好后，复制一份配置指向它：

```powershell
Copy-Item E:\Strata\fork-8090.json E:\Strata\fork-8090-game.json
# 改三处：--pack / --native / --ple-gguf 指向新模型，port 改成 8091
```

**注意**：一张卡同一时间只能跑一个模型。所以对比是**交替启动**，不是同时。

## 1. 对比原则

| 项目 | 规定 |
|---|---|
| 引擎 | 同一个 `strata.exe`，同一份 env |
| 参数 | `--max-context 65536`（只比质量时够用）、`--kv int8`、`--prefill auto`、`--spec` 相同 |
| 采样 | `temperature 0`（greedy），避免随机性 |
| 预热 | 每个模型先发 3 个请求，之后才计时 |
| 顺序 | A(旧) → B(新) → A(旧) → B(新)，两轮取中位，抵消热漂移 |
| 记录 | 原始输出全部存盘，人工盲评 |

## 2. 质量测试集（20 题，五类各 4 题）

**用你项目里真实遇到过的问题**，不要用 benchmark 题。下面给的是模板。

### A. 数学 / 图形学（4 题）

- 推导某光照模型的 BRDF，并给出 GDScript 实现
- 给定两个四元数，求插值并解释为什么不能直接线性插值
- 计算一个包围球/AABB 的相交判定，给出复杂度分析
- 一个具体的积分/级数展开，要求给出中间步骤

### B. 着色器代码（4 题）

- 写一个具体效果（例：菲涅尔边缘光 + 三平面噪声扰动），HLSL 和 GLSL 各一版
- 给一段有 bug 的 shader，要求定位并修复
- 把某个 CPU 端效果移植到 vertex/fragment
- 解释并优化一段过度采样的循环

### C. 游戏逻辑代码（4 题）

- GDScript 实现一个具体系统（状态机 / 对象池 / 存档序列化）
- 给定一段 C++ 找出内存/生命周期问题
- 写一个编辑器工具（导入管线 / 资源校验）
- 重构一段重复逻辑，要求不破坏行为

### D. Agent 多轮任务（4 题）

需要 3~5 步工具调用的任务，例如：
「在项目里新增一个 XX 功能，改 2 个文件，跑测试，修掉失败」

**记录：任务是否完成、用了多少轮、有没有陷入循环、工具调用是否正确**

### E. 工具调用正确性（4 题）

- 给定工具 schema，让模型生成调用：检查 JSON 合法性、必填字段、类型
- 故意给模糊需求，看它会不会乱填参数
- 多工具选择：看它选不选对工具
- 错误恢复：工具返回错误后，下一轮是否合理

## 3. 质量评分表（人工盲评，5 分制）

把两模型的输出**打乱顺序、去掉标识**，逐题打分：

| 分值 | 含义 |
|---|---|
| 5 | 可直接用，无需修改 |
| 4 | 小改可用 |
| 3 | 需要明显修改 |
| 2 | 方向对但基本不能用 |
| 1 | 完全错误 / 答非所问 |

```
2     数学      ___        ___
...

------------------------------------------------
合计            ___        ___        （满分 100）
```

**判定线：B（新模型）总分 ≥ A 的 95% 才算不劣化。**

## 4. 速度测试（自动，三次取中位）

对每个模型，用固定提示词测这几个点：

| 指标 | 测法 | 现有 IQ4_XS 基线 |
|---|---|---|
| 预填 8K | 8,000 token 提示词，看 `prompt_ms` | ~3 s |
| 预填 32K | 32,000 token | ~12 s |
| 预填 100K | 100,000 token | ~37 s |
| 解码短答 | 200 token 输出，看 `decode_tok_s` | 68~77 tok/s |
| 解码长答 | 1,500 token 输出 | 68~77 tok/s |
| 首 token（冷） | 新会话第一个请求 | 30~48 s |
| 首 token（热） | 同会话第二请求 | 1~3 s |
| 50 轮长会话 | 连续 50 轮后测解码 | 不低于基线 90% |

**判定线：解码下降 ≤ 10%，预填下降 ≤ 15%。**

## 5. 资源对比

| 指标 | 怎么取 | 现有 |
|---|---|---|
| 模型体积 | 文件总大小 | 93.7 GB |
| 引擎工作集 | `strata.exe` 的 WS | 72.3 GB |
| VRAM 占用 | `/metrics` → `expert_cache_mib` | 14,122 MiB |
| 专家缓存命中率 | 日志 `decode expert cache hit rate` | 75~80% |
| 会话缓存淘汰 | `/metrics` → `evictions` | 0 |

---

## 6. 稳定性

- 连续跑 50 轮，看有没有循环、退化、上下文错乱
- 超长提示词（≥ 100K）跑 3 次，看有没有崩
- 对照日志里有没有 `no progress` / `stall` / `0xC0000409`

---

## 7. 最终判定

三项**全部**满足才替换：

- [ ] 盲评总分 ≥ 旧模型 95%
- [ ] 解码速度下降 ≤ 10%
- [ ] 体积 ≤ 100 GB

任何一项不过 → **保留 UD-IQ4_XS-v31**，特化版留作备选。
