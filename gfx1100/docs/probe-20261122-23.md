# 底层调优实验记录（2026-11-22/23）

> 目标：在不降低质量的前提下，从配置、内核、量化三个层面找 decode 的提速空间。
> 结论先行：**所有代码/配置层面的手段均已试过，净收益 +4%（`--adapt-min-gain 1.8`）；剩余空间只能靠硬件。**

## 测试环境

| | |
|---|---|
| GPU | RX 7900 XTX 24 GB（gfx1100），HIP SDK 7.2 |
| CPU / RAM | Ryzen 7 9700X（AVX-512）/ 126 GB |
| 模型 | Qwen3.8-Flash-Next，Unsloth UD-IQ4_XS v31，4.23 bpw，87.24 GB |
| 引擎 | fork 0.1.49.1（14 文件补丁），`--kv int8`，`--spec 4 --spec-min-p 0.5`，`--adapt-every 1 --adapt-swaps 32 --adapt-decay 0.97`，`STRATA_HIPBLASLT_TABLE=on` + 100401 表 |
| 方法 | 固定 prompt、`max_tokens 256`、`temperature 0`、每次改配置完整重启、取暖机后中位数；分阶段数据用 `STRATA_DECODE_TIMING=1` |

## 基线：decode 的阶段分解

一个 256-token 请求（47–58 窗口）：

```
25.4 ms/window = verify 21.9
                 ├ GPU-reach 等待  8.96
                 ├ 每层 host      10.35  (其中 CPU 专家 9.99, plan 0.16, actq 0.12, jobs 0.02)
                 └ stage           0.05
               + commit/emit      0.16
               + draft            2.32
               + adapt wait       1.0
每窗口：CPU 专家 ~4.1 个、VRAM 命中 ~26.9 个、PCIe 0.00
```

**关键结论：CPU 专家计算（9.99 ms，40%）和 GPU 计算（8.96 ms，35%）基本串行**——同一层的合成要等两边都完成，这是结构性的。

## 配置层实验

| 实验 | 结果 | 判定 |
|---|---|---|
| `--spec 5 --spec-min-p 0.70` | 93.3 vs 99.5 tok/s（**−6%**） | 否决（#6476 的结论不适用于 IQ4_XS + XTX） |
| `--adapt-every 0` | 68 vs 99.5（**−32%**） | 否决（自适应专家缓存是命脉） |
| `STRATA_ROUTE_TAIL_SKIP=7` | +6.4% 速度，但 12 条答案 6 条变化（对照组本身 3 条会变） | 否决（质量漂移） |
| `STRATA_SPEC_COST=1` | 95.3 vs 99.0（−4%） | 否决 |
| KV `fp16` / `k8v4` / `q4_0` | decode 83.4 / 72.2 / 63.8 vs int8 的 90.7 | 否决（4-bit 注意力路径未优化，反更慢） |
| `--max-context 131072` | 70.9 vs 67.2 wall，VRAM 余量几乎不变 | 噪声，无效 |
| `--pipeline-windows 2` | 29.30 vs 25.85 ms/window（**−15%**），adapt join 4.25 ms | 否决 |
| **`--adapt-min-gain 2.0`** | **98.8 vs 94.6（+4.4%）**，两个配对轮次均为正 | **采纳，定为 1.8** |

采纳改动的机制：`ms/window` 几乎不变（25.82→25.63），`tokens/window` 由 2.44 升到 2.53 —— 交换次数减少后对草稿/验证的干扰变小。

### `adapt-min-gain` 细化扫描（1.5 / 1.8 / 2.0 / 2.5 / 3.0）

单轮（每档一次）：

| gain | 1.5 | 1.8 | 2.0 | 2.5 | 3.0 |
|---|---:|---:|---:|---:|---:|
| 第 1 轮 decode | 99.6 | 98.0 | 95.8 | 94.7 | **113.7** |
| 第 2 轮 decode | 91.9 | 99.5 | 88.8 | 104.2 | 97.4 |

3.0 的 113.7 是离群值，遂做 1.8 vs 3.0 的三组配对：

| 配对 | 1.8 | 3.0 |
|---|---:|---:|
| 1 | 82.7 | 86.7 |
| 2 | 103.3 | 93.8 |
| 3 | 96.6 | 97.4 |

合并 5 个样本：

| gain | 均值 | 标准差 | tok/window | ms/window | swaps/window |
|---|---:|---:|---:|---:|---:|
| 1.8 | 96.0 | 8.0 | 2.49 | 26.57 | 31.4 |
| 3.0 | 97.8 | 9.9 | 2.38 | 25.67 | 26.7 |

配对差分均值 +1.8%、标准差 9.6（t≈0.4），**不显著**。3.0 让 `ms/window` 稳定低约 3%，但 `tokens/window` 同时略降，两者抵消。

原因：`adapt-min-gain` 只决定"差距多大才值得换入"，1.8→3.0 把交换从 31/窗口降到 27/窗口；在 70–85% 命中率下，更保守换入的边际收益被"热专家未换入"抵消。

**结论：保持 1.8。**

## 内核层实验

### 1. AVX-512 IQ4_XS（自写，已回滚）

`iq_avx512.cpp` 覆盖 IQ2_XXS/IQ2_XS/IQ3_XXS/IQ3_S/IQ2_S，**不含 IQ4_XS(23)**。实测原因（代码注释）：多 token 内核在单 token 时**并不更快**，"all are bound by the codebook lookups, ~5 GB/s per core"。decode 是单 token，故 AVX-512 无效。实测 25.44 vs 25.42 ms，CPU 9.69 vs 9.99（噪声内）。

### 2. `STRATA_EXPERT_V2`（分组解码）

该路径只实现 IQ3_S/IQ4_NL（S2 2-bit 格式，`QK=64`、每行 640 B），IQ4_XS 不适用。实测 96.0 vs 103.1（−7%）。

### 3. MMVQ wave 配置扫描

`STRATA_RDNA_MMVQ_WAVE` = 0/1/2/3：

| 值 | ms/window | decode |
|---|---:|---:|
| 0（通用） | 25.28 | 96.5 |
| 1（全部 wave） | 24.79 | 98.4 |
| 2（小格式） | 27.27 | 93.9 |
| 3（精确，现行） | 22.67 | 93.5 |

四档在 ±5% 内，**无显著赢家**。

### 4. 带宽微基准（gfx1100，4 GB 显存数据）

| kernel | GB/s |
|---|---:|
| 纯流式读 | 938–992（标称 960，已压满） |
| IQ4_XS 反量化 + 点积 | 973–978（**≈纯读**） |

→ 反量化 nibble 的开销 ≈ 0，matvec 本身已在带宽墙上。

### 5. 派发粒度（重要，但不可外推）

| 结构 | 2048 行 / 17 MB | 有效带宽 |
|---|---:|---:|
| 每行一次 launch（1 block） | 1.8–4.9 ms | 3.6–9.8 GB/s |
| 行内切 8 block | 2.6–5.1 ms | 3.5–6.9 GB/s |
| **8 行 / 一个 block** | 0.02–0.05 ms | **350–941 GB/s** |
| 持久化 + 队列 | 0.04–0.10 ms | 171–509 GB/s |

**但这不代表引擎**：`native_iq4_xs_mmvq` 每次 launch 已是 `n_out/4` 个 block（gate/up 160、down 640），96 个 CU 吃得下。结合 wave 扫描无差异，**"派发是瓶颈"不成立**，多专家合并预期收益 <6%，不做。

## 对照模型：Inkling 2 Mini（SQ-20，SF4+MX8，19.35 GB）

| 场景 | Inkling | Qwen3.8-FN |
|---|---|---|
| 短答 decode | 86–96 t/s | 92–99 t/s |
| 28K 上下文 decode | **32 t/s** | ~90 t/s |
| 28–38K prefill | 2,194 t/s | ~2,190 t/s |
| 12 条基础任务 | 全对 | 全对 |
| 鹈鹕 SVG | 构图混乱、车架交叉 | 结构完整、部件齐全 |
| 单车 SVG | 及格（4 根辐条、平把） | 精细（密辐条、弯把、牙盘） |

结论：Inkling 适合短上下文/结构化任务的轻量副手；长上下文弱 3 倍，复杂构图弱。与量化无关（SQ-20 相对原模型 100% 逐 token 一致）。

## 测量噪声（重要）

同一配置重复测量（每次完整重启、同一 prompt、temperature 0），decode 可落在 **82.7–103.3 tok/s**，即 **±10% 左右**。因此：

| 量级 | 是否可信 |
|---|---|
| ≥15% 的差异（`adapt-every 0` −32%、`pipeline-windows` −15%、官方 0.1.64 −23%） | 可信 |
| ±5% 以内（`adapt-min-gain` 1.8 vs 2.0、MMVQ wave 四档、`spec 5`） | **不可当定论** |
| 同一配置的重复测量 | 必须配对、至少 3 次，取中位数并看散度 |

这也是为什么上文把 `--adapt-min-gain` 的收益写成"约 +4%"而非精确值，以及为什么不能用单次跑分否定任一开关。

## 最终结论

1. 这台机器 + UD-IQ4_XS 的组合，**代码/配置层面已到顶**：净收益只有 `--adapt-min-gain 1.8` 的 ~+4%。
2. decode 的 40% 花在 CPU 码本查表、35% 在 GPU（已在带宽墙上），两者因同层合成而串行 —— 这是该模型/引擎结构的固有开销。
3. 再快只能换硬件（更大显存容纳更多专家 / 更大内存跑更大模型），或接受更低量化的质量损失。
